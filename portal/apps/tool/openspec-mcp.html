📐 OpenSpec 使用指南

在你的 AI 编程工具中管理项目规范、提出变更、跟踪任务，让每次开发都有清晰的依据。

你需要一个可登录本服务的账号，以及支持 MCP 的 AI 编程工具。OpenSpec 提供规范与变更管理；AI 模型由你使用的客户端提供。项目源码可以继续放在 GitHub。

1. 准备你的项目

新项目请打开 项目申请表，登录后按表单填写项目名称、GitHub 仓库地址等信息并提交。保存提交后返回的申请链接，用它查看审批进度和处理结果。

审批通过后，即可在 AI 客户端中选择该项目。如果要加入已有项目，请联系项目管理员为你的账号开通访问权限，无需重复申请。

首次使用时，登录账号与 Gitea 账号的邮箱需要一致，用户名可以不同。遇到账号关联问题，请联系管理员。

2. 连接你的 AI 客户端

选择下面与你使用的客户端对应的方法，完成配置后，在浏览器中登录并授权。

配置项填写内容
服务名称openspec
MCP 地址https://openspec.panghuer.top/mcp
传输方式Streamable HTTP
认证方式OAuth（浏览器登录授权）
Client ID315cbdaf565b82103c6f
Client Secret留空，不需要填写

直接通过 OAuth 连接时，请使用上面的 Client ID。它是本服务共用的公开应用标识，不是你的个人令牌，无需自行申请。如果使用已配置好的本机网关，则按网关说明连接，无需在 AI 客户端重复填写这个 ID。

Claude Code

在终端执行：

claude mcp add --transport http --client-id 315cbdaf565b82103c6f openspec https://openspec.panghuer.top/mcp

进入 Claude Code，使用 /mcp 查看连接状态，并按提示完成 openspec 的登录授权。

Codex CLI

在终端依次执行：

codex mcp add openspec --url https://openspec.panghuer.top/mcp --oauth-client-id 315cbdaf565b82103c6f
codex mcp login openspec

完成浏览器授权后，启动或重新打开客户端会话。若提示不支持上述参数，请先更新客户端。

其他客户端

在客户端的 MCP 设置中添加远程服务，按上表填写地址、传输方式和 OAuth Client ID，再完成登录。不同客户端的设置入口和 OAuth 支持情况可能不同。

如果客户端不支持 OAuth 或无法指定 Client ID（例如需要通过网关接入的 DSH），请见下一节。

不支持 OAuth 的客户端（如 DSH）：经本机网关接入

有些客户端的 MCP 实现不走 OAuth 授权码流程，也无法携带 client_id —— DSH 的 MCP 客户端就是这种情况（按其源码实测确认）。这类客户端不直连 openspec.panghuer.top，而是连一个只监听本机的小网关：由网关代为完成「发现 → 浏览器授权 → 令牌续期」，客户端只拿一个本地令牌，真正的长期凭据不出现在任何配置文件里。

这套方式是本机 DSH 目前在用的配置，与下面的通用表一一对应：

配置项填写内容
服务名称openspec
MCP 地址http://127.0.0.1:33419/mcp（网关端口，只监听本机）
传输方式Streamable HTTP
上游地址https://openspec.panghuer.top/mcp（由网关配置）
认证方式自定义请求头 x-mcp-gateway-token，值为网关的本地令牌
Client ID不需要填（由网关代填 315cbdaf565b82103c6f）

客户端侧配置片段（DSH 的 profile patch；其他客户端写成对应的 headers 即可）：

- insert:
    - id: openspec-mcp
      name: "@deepseek-ai/dsh-mcp-client"
      config:
        serverName: openspec
        transport: streamable-http
        url: http://127.0.0.1:33419/mcp
        headers:
          x-mcp-gateway-token: '<网关的本地令牌>'
        failOnStartupError: false
        reconnect:
          maxAttempts: 20

本地令牌由网关自己生成并保管，不在服务端任何配置里，位置是：

%APPDATA%\mcp-oauth-gateway\<state>.json      # 取其中的 localToken 字段
不要把本地令牌写进公开页面、代码仓库或工单。它只在本机有效，但泄漏后本机上任何程序都能用它访问你可访问的 OpenSpec 项目。需要更换时：改状态文件里的 localToken → 同步客户端配置 → 重启网关。

首次连接或授权过期后，在浏览器打开网关的登录页完成授权，然后重新连接客户端：

http://localhost:33419/oauth/login

网关可以设为开机自启（本机用的是 wscript %APPDATA%\mcp-oauth-gateway\serve-hidden.vbs）。连接成功后，用第 3 节的「列出我可以访问的项目」验证即可。

3. 选择项目并确认连接

在 AI 客户端中发送：

请通过 openspec MCP 列出我可以访问的项目。

看到项目列表后，选择这次要开发的项目，并发送下面的指令，将占位内容替换为实际信息：

本次使用 OpenSpec 项目「你的项目名称」，projectId 为「列表中返回的 ID」。
请读取该项目的现有规范和未完成变更，概括当前状态，先不要修改内容。

能够读取项目内容，就说明接入成功。新项目没有规范或变更是正常的，可以从第一个需求开始。

打开本地代码目录不会自动选择 OpenSpec 项目。新会话或切换项目时，请明确告诉 AI 使用哪个项目，避免把变更写到其他项目。

日常怎么使用

  1. 描述需求，先形成变更提案

    告诉 AI 你想实现的功能，让它先读取现有规范，再整理提案、规范变更和任务清单。检查内容是否符合你的预期。

    请为当前 OpenSpec 项目创建一个变更：添加用户收藏功能。
先读取相关规范，整理提案、行为与验收场景、开发任务。
有不明确的地方先问我，暂时不要修改代码。
  2. 确认方案并校验

    让 AI 按你的反馈更新变更，并调用 OpenSpec 校验。校验通过表示文档符合要求，功能是否满足需求仍需要你审阅。

    请根据刚才的反馈更新这个变更，并执行 OpenSpec 校验。
告诉我校验结果和还需要确认的问题。
  3. 实现功能，记录进度

    方案确认后，让 AI 在你的源码工作区实现并测试，同时更新变更中的任务清单。代码修改和测试由你的开发工具完成。

    方案已确认，请按这个变更的任务清单实现并测试。
完成后更新任务状态，说明测试结果和剩余事项。
  4. 完成验收，归档变更

    确认实现和测试结果符合要求后，让 AI 再次校验并归档变更，将规范变更纳入正式规范。归档需要项目管理员权限；没有权限时，请联系项目管理员完成。

    这个变更已完成验收。请检查任务状态并再次校验，
确认满足归档条件后归档，将结果告诉我。

你也可以随时让 AI「列出当前规范」「查看未完成变更」或「总结某个变更的进度」。通常不需要自己编写 API 请求或填写工具参数。

常见问题

遇到的情况如何处理
连接时要求 Client ID，或提示客户端注册失败填写 315cbdaf565b82103c6f，Client Secret 留空；若客户端没有对应设置，请使用支持该配置的客户端或本机网关。
提示未授权或登录已过期在客户端重新登录 openspec 并完成浏览器授权。Codex CLI 可执行 codex mcp login openspec。
能连接，但项目列表为空或找不到项目确认登录的是申请项目时的账号，检查申请是否已通过；已有项目请联系项目管理员确认访问权限。
可以查看，但不能修改或归档联系项目管理员确认你是否有相应权限。查看权限不代表可以修改；归档需要管理员权限。
提示会话失效（session expired）在客户端重新连接 MCP，必要时重新打开客户端会话，再选择项目。
提示版本冲突（409）让 AI 重新读取最新内容，核对其他人的修改后再提交更新。
变更校验失败让 AI 根据返回的问题修改变更文档，然后再次校验。
服务无法连接，或返回 502 / 503稍后重试；持续失败时，将错误信息和发生时间提供给管理员。
