The independent Pi worker and supporting API/UI are deployed at
https://scientific-agent.panghuer.top/. The final image passed 182 regression
tests and 7 Linux isolation checks, all with zero failures/skips. A Chinese
research task submitted through the authenticated browser completed and passed
report, evidence and download verification. CrewAI remains the default; select
`pi` and `brief` explicitly for this demonstrated workflow.

Full acceptance remains open for F4, E7 and I1.2, as detailed below. The change
is not applied or archived. Earlier failures and narrower probes are retained
as evidence, not overwritten by the final success.

## Real controlled research and public sources

A real Pi 0.73.1 / Node 24.21.0 process and real gateway completed the controlled
two-paper contradictory-abstract task in 143.213 seconds, with 11 model requests
and one publication ACK. The actual validator, SQL projection, report download
and artifact hashes passed. Skill reading and UID 200000 cleanup were verified.
This used fictional research material and an isolated in-memory report store.
Its JSON evidence is [controlled-research-result.json](evidence/20261022-rollout/controlled-research-result.json).
The report bytes were checked during the run; the completed Pod's temporary
Markdown file was not retained after kubelet reclaimed its memory volume.

The worker-specific HTTPS resolver uses fixed AliDNS bootstrap addresses with
certificate/hostname validation, accepts only global IPv4 answers for supported
academic hosts, connects to that exact address with the original SNI/Host, and
rejects redirects, private/fake addresses, oversized replies and proxy env.
It is scoped through a ContextVar around the Pi academic bridge; ordinary
CrewAI HTTP behavior remains the original implementation.

On the actual worker image, paired unrestricted/restricted Pods on
`orangepi5-max-server1` passed LLM health, Crossref/PubMed/arXiv verified HTTPS
and expected payloads, one real search result from each source, and DOI/PMID
identifier lookup. Kubernetes API, Vault, SQLite, Redis and node SSH were
reachable in the baseline and blocked in the restricted Pod. Human Pi is
already protected by its target-side policy, metadata has no available
baseline service, and there is no routable IPv6: these are explicitly unknown
for this paired test, not claimed successes. See [network acceptance](../../panghu_agent/docs/scientific-pi-network-acceptance.md).

## Production configuration

The worker is a single Recreate deployment with a dedicated Ceph RBD RWO 10 GiB
PVC. It has no public ingress or service-account token. The controller retains
only the reviewed five capabilities; each Pi attempt uses a fresh persistent
UID allocation. Its model ingress label `llm-client=true` is required by the
gateway policy installed on 2026-10-17. The renderer now supplies that label
only for the internal gateway, without widening workload selectors.

The control token lives at Vault `secret/scientific/pi-worker`; the separate
model caller is `LLM_TOKEN_SCIENTIFIC_PI` at `secret/llm-service/callers`.
ExternalSecret reads each authoritative location directly. Both values were
generated in memory and written with CAS/readback; no values were logged or
stored in Git. Existing caller values were preserved. The gateway completed
its standard rolling restart to load the additional caller.

The production child can read its dedicated model caller key, as designed.
It cannot inherit worker control, Vault, database, SMTP or human Pi credentials.
The controlled model probe's dummy-key loopback proxy is a test harness and
does not describe the production credential architecture.

The API keeps `SCIENTIFIC_DEFAULT_ENGINE=crewai`, uses the dedicated image and
explicit module entrypoint, and retains the existing CrewAI overlay. No API
egress policy was added: the existing API had no egress isolation. The UI uses
its original running image pinned to
`sha256:4639d4c6d2cfbd03a26cb759f7badbc2b4fabaa988e3299adbbb00d6a7d2c482`
and a separate immutable source ConfigMap. It exposes Pi/brief selection,
optional email, task lookup/cancellation and report downloads. Its explanatory
text now describes actual evidence limitations without promising a systematic
review or a fixed runtime.

## Retained rollback procedure

Keep the production PVC and shared report records. Before API/UI rollback,
stop new Pi submissions, keep CrewAI as the default, and let existing Pi tasks
finish or cancel them through the documented API. Check there are zero active
CrewAI tasks before replacing the API Pod. Original specifications were saved
before the rollout in the protected server backup directory stated above.

To prepare reviewable rollback patches from those saved specifications:

```python
import json
from pathlib import Path
root = Path('/root/scientific-pi-rollout-20261022')
for name in ('api', 'ui'):
    saved = json.loads((root/'backup'/f'scientific-agent-deployment-{name}.json').read_text())
    patch = [{'op': 'replace', 'path': '/spec', 'value': saved['spec']}]
    (root/f'rollback-{name}.json').write_text(json.dumps(patch))
```

Review the files, then use `kubectl --kubeconfig=/etc/kubernetes/super-admin.conf
-n scientific-agent patch deployment/<api-or-ui> --type=json
--patch-file=/root/scientific-pi-rollout-20261022/rollback-<api-or-ui>.json`.
After task drain, scale only `deployment/scientific-pi-worker` to zero if
suspending Pi. Leave its PVC, ExternalSecret and published reports intact.
The dedicated caller can remain provisioned; this rollback does not require
changing shared gateway routing or any Casdoor record. These are prepared
rollback instructions, not a claim that rollback was executed.
