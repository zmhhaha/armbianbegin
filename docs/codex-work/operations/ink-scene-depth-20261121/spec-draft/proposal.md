# 统一场景空间、分层、镜头与渐进式参考学习

## Why

当前绘图库和影片模块已有分层缓存、镜头计算及局部动态，但空间语义、跨镜头连续和复用规划散落于各模块。仅按时长生成更多独立场景增加模型开销，也容易产生比例、依附、遮挡和场景切换问题。图片学习、视频学习及效果库还需要共同描述与逐步验证空间、分层和镜头方法。

用户已确认：少数完整场景供片内多镜头复用；对象级布局与风格相关网格；Canvas、SVG/HTML、Three.js 共享上层语义；全自动编排在开始时决定镜头动静及局部动画，无强制动效默认；自动预演与有限修正；模型与渲染分别设有界预算，预算不足则停止正式成片、保留最佳预览。好的效果经效果库和显式 WikiSkill 发布影响后续任务，本轮不建立自动跨影片场景资产库。

## What Changes

- 设计版本化的场景世界、对象/锚点/区域/尺度/深度/依附/遮挡、镜头及执行区间语义，区分风格相关逻辑深度与真实几何深度。
- 统一规划镜头覆盖范围、分层、局部动态与复用，再准备必要画面；以受控计划修订、绝对时钟重放和有界缓存支持后续执行。
- 将共同语义用于图片学习、视频学习和效果方法，逐步完成观察、空间假设、有界复现、时间学习和反馈比较，保留来源、置信度和实际验证范围。
- 明确旧图片静态合同、旧视频 `sampled_frames_only` v1 不证明运动；真实时间观察需要新版本合同、能力准入和独立验证。
- 设计风格相关的技术、空间与视觉门控、有限局部修正及独立模型/渲染预算，保留失败、最佳预览和变更记录。
- 维持效果精选、整库 WikiSkill 显式发布、批次冻结、知识开关及执行依赖的既有边界。

本次交付是设计文档和映射 OpenSpec 规格、任务。后续实施涉及规划及模块合同、各渲染适配、图片/视频学习、效果方法证据与 WikiSkill 编译消费的兼容演进。本文不宣称代码、部署、时间证据合同或学习能力已经实现。
