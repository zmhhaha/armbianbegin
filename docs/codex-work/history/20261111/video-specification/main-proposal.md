## Why

用户确认以通用 Agent 的创作方法改善动画表达，并让完整效果样片、结构迁移、认可发布和正式制作形成可追溯闭环。最初复核时的固定题库、单次修订与源码优先草案属于旧基线；效果库新入口、真实续作和正式方法读取接线已经实施，后续按实际作品、发布与正式采用证据继续验收。

用户已持续授权分阶段开发、真实有界验证、完整 Git 源码构建部署；方法发布仍需开发者认可具体样片和迁移，主线合入按用户另行指示。最初“只核查和规划”的授权边界是历史阶段，不约束随后明确批准的实施。任务完成状态见 tasks.md，不从规划、代码或部署状态推断人工质量认可。

多图层表现力优化本次仅登记为后续讨论，当前先完成既定任务，不新增实施或验收范围。

## What Changes

- 创作方法是主要复用对象，按表达问题组织；Agent提炼、维护并组合方法，工程提供运行、渲染和验证。样片源码可辅助学习与复现，不以复制源码为复用前提。
- 完整效果样片与方法独立、多对多关联。样片保留铺垫、过程、结果，默认无讲解旁白但允许必要音效，无固定8秒、单镜或首帧全显限制。
- 参考或目标先形成少量可观察标准，开发者可调整；独立评审比较完整连续样片及必要声音，重点是过程与因果。技术通过、模型评价、实际改善和人认可分别记录。
- 单次开发者委托可在显式预算内自主多轮探索；目标达成、预算耗尽或多种尝试无明显收益时停止，交付最佳结果、问题和原因；之后可继续优化，不受正片1+2约束。
- 先深入代表片段，在里程碑用少量真正不同的任务验证迁移；失败反馈到方法，回归原片和受影响案例，发布前验证与改动范围相称。
- 开发者主要看样片、比较和迁移，用自然语言反馈；Agent维护方法，详情可展开。开发者认可样片及迁移后发布确切方法版本，未发布候选不进入正式方法检索。
- 正式Agent按需实际读取、选择、组合已发布方法；记录输入和应用依据。版本冻结、无匹配自由创作、项目新效果不自动共享发布。
- 正片由Agent联合策划，一次整体确认后生成配音，以实测时长和全片上下文创作；默认一轮打磨，用户可明确追加最多两轮，之后按明确需求列表局部修改。
- 样片效果库成为实验室主入口，技术回归和日志移入内部工具或详情，旧测试作品和标注无需迁移；无用旧入口按新目标退场。
- 音效编排、真实音轨和试听进入首批闭环；Canvas／Three自由源码逐引擎准入，不新增公共渲染服务。

## Capabilities

### New Capabilities

- reference-animation-effect-library: 方法与完整样片、多对多验证、目标评价、持续实验、迁移和开发者认可发布。
- agent-directed-video-production: 已发布方法的选择组合、联合策划、音频先行、整片上下文与真实媒体独立审阅。
- bounded-visual-revision: 仅正片的一轮自动、最多两轮用户追加与后续明确需求边界。

### Modified Capabilities

None. Existing audio-clock draft tasks share implementation and evidence through the explicit cross-references in design.md; completed historical requirements are not retroactively reinterpreted.
