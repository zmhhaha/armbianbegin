## Decisions

采用有限注册需求库和确定性编排：每条需求保存完整结构化brief及原文稿；按模块/领域/引擎/复杂度生成有种子的覆盖清单和冻结产物。首轮手工审校的结构化需求避免无界模型生成和费用。显示原生技术采样、人工评价及生产准入的真实范围，不将静音样例当配音同步。

新SVG/HTML家族使用独立版本化编译器；HTML操作必须是真实DOM状态变化。所有状态从绝对时间推导，任意倒放复原。Canvas与Three使用领域语义明确的v2计划和技术review，Three保持本地固定模块与真实WebGL。

按用户最新要求整体重建活动样例库，仅保留27个新需求作为cross-domain-requirements-v2基线。旧15例仅可作为内部编译组件测试，不公开旧ID；专用Lab数据库一次性清空旧快照、意见、评测分流和迭代任务，同基线重启保留新标注。已挂载的旧评测报告不得重新注册到新库。不更改业务数据库、媒体和项目归属；全仓临时目录清理仍属以后统一清理任务。

跨域评测同时检查数量、单位、守恒关系、真实SVG路径/柱形几何、算法trace及实际界面状态，真实截图与DOM检查绑定精确输入和资源。候选A/B保持相同数据和结论。新增模块接入反馈任务、runner允许文件和固定测试。sample_identity表示输入与产物；lab_snapshot_identity表示工作台存储快照；需求集v2的semantic_identity跨CLI和HTTP一致，完整identity还绑定runtime和快照。

首轮不是任意需求生成器，不是生产自动选型。之后经开发者评价再逐步扩展生产计划，保留每例production_admitted=false。
