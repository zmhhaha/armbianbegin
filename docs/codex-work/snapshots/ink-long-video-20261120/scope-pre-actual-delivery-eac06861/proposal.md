# Publish current ink knowledge and produce a five-minute landscape film

## Why

At the start of this task the active WikiSkill was release sequence 1. Recent picture experiments, free composition and newly documented ink techniques had not been republished, formal film consumers rejected drawing-library dependencies, and whole-film execution stopped at 60 seconds while retaining every PNG frame on disk. The requested five-minute landscape film needs this knowledge and runtime supply plus reliable continuation after a later module author fails.

## What Changes

- Freeze the ink-landscape revision available when this task began (`b6c96a5e94124bfad8113aaa136ede2298151b5f`) with its complete bounded publication documentation and explicit verification limits.
- Include observed free-composition and failed-learning facts as traceable sources, without inventing artistic approval or dynamic validation.
- Admit the exact drawing library and local bytes into formal film authoring, knowledge filtering, module assets and the whole-film snapshot.
- Add a separately identified long-film capture path with bounded temporary storage and one continuous final encode from a single root project and absolute frame clock.
- Explicitly publish one new WikiSkill release, bind it at the beginning of one new production batch, and inspect actual search/read and library execution evidence.
- Produce and inspect a real 300-second landscape film through formal planning, module creation, whole-film rendering and delivery.
- Allow an explicit fresh silent production attempt to reuse a verified contiguous completed prefix from a stopped failed run with identical frozen inputs; retain original sources, versions and failure history and generate only the unfinished suffix.
- If all modules completed and the sole whole-film render failed with positive stop proof, allow an explicit fresh standard attempt to reuse every verified original module and perform only one new whole-film render. Preserve the stopped render, snapshot and failed run; diagnose the actual export failure before retrying.
- For this stopped complete film, admit any required renderer repair through a server-owned exact source-to-target runtime policy scoped to the original film and ordered package inventory. Retain original author identities and source bytes, require a separately admitted target renderer, and keep every new execution snapshot and receipt bound to that real target.

## Impact

Touches versioned runtime capability/compatibility contexts, vendor/publication sources, film production configuration and export. Existing published releases and frozen legacy tasks retain their meanings. Installation and experiment completion still do not automatically publish knowledge. Per-shot limits remain bounded; this change does not concatenate separately rendered shot videos or claim that a still image establishes film quality.
