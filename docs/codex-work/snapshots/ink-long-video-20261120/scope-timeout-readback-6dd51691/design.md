# Design

The new film begins from a real published WikiSkill release. Code availability, publication, delivery, actual skill reads, visible library use and artistic judgment have separate evidence. Production input cannot grant itself a library by adding its name to metadata: server-owned runtime capabilities must admit the exact descriptor and every asset hash.

The source revision is fixed at b6c96a5. A later repository HEAD is outside this snapshot. Documentation under the library learning directory must be captured explicitly; embedded reading data and five Skill files are not a substitute for publication sources. Sources may describe failed rendering and low visual quality, but retain those outcomes and static-only limits. Local files are imported as image-owned content with provenance rather than becoming runtime filesystem dependencies.

The formal runtime adds a versioned drawing-library slot with old capability and compatibility schemas still accepted. New module requests receive the neutral API contract and exact local code/license. Host source, library bytes, release identity and scene assets are frozen in the same production snapshot. Closed, missing or incompatible knowledge is reported honestly; filtering is not bypassed.

Long execution uses a distinct capture contract. Frames come from one root HyperFrames project at exact frame_index/24 times and feed one ffmpeg encoder with bounded in-flight buffers or small batches. All 7200 PNG files must not accumulate. Source identity, per-frame hashes, selected deterministic seek probes, complete media decoding, timing, audio sample accounting and cancellation cleanup remain verifiable. Old short-film captures and receipts keep their old interpretation.

The five-minute scenic film has no explanatory narration. The formal plan determines bounded shots and time-based camera, fog, vegetation and boat movement. The explicit no-narration clock is not represented as recorded speech. Sound is used only through actually admitted facilities. The deliverable is a real continuously encoded 300-second MP4, with visual sampling and continuous playback inspection; a five-minute repeat of a short sample is not an acceptable substitute.

Actual publication exposed a separate control-path limit: 1031 frozen files produce a roughly 39.7 MB execution identity, and inspect/renew/events repeatedly reopened the complete input set. A database lease renewal could therefore reach the Worker too late. The first ordering repair was insufficient and both failed attempts remain immutable. The follow-up repair uses a server-owned compact control identity only after the original full-byte admission and native-start claim. Each operation must match the durable owner, caller, original request, attempt, fence, pins and physical allocation. Compact identities cannot start a native Worker. Historical records without the new intent binding retain the full validation path. Tests, measured large-input control timing and a fresh explicit publication must establish the repair; a database expiry value alone is not evidence that the Worker received a renewal.

A third attempt proved repeated Worker lease delivery and real model/source-reading activity, but still failed its unchanged 900-second deadline before native result submission. Original model writes are preserved only as diagnostic artifacts; a locally valid replay is not a successful native result or a publication. New publication jobs therefore freeze a versioned 1200-second business window, retain the existing admitted native maximum of 900 seconds, and reserve 250 seconds for outer result collection and atomic publication. Upload time can tighten the native window, never extend a previously accepted task. Historical jobs without the new timing marker retain their original request, deadline and terminal outcome. The native execution and its internal result/stop processing remain subject to the existing 900-second Agent contract.

The next attempt exposed schema errors whose full-output repair exceeded the native window. A deliberately opt-in recovery source may therefore copy the exact retained model write-call proposal, its failed/stopped provenance, original source-index mapping and separately labelled operator schema findings into a fresh publication snapshot. The source is invalid, unpublished text, not a successful native output, check receipt, original-source read, or artistic approval. Its raw bytes must equal the sanitized preserved write-call content. Only generic provider code is in Git and the application image; actual drafts, provenance and private source identifiers stay in the owner-scoped application-data directory, pinned by operator-selected manifest hash. The new Agent must read appropriate originals, repair metadata and links itself, bind the new input and snapshot hashes, and complete the standard write/check/stop path. The host never supplies a corrected Skill. Disable the temporary recovery capture after successful publication so future snapshots do not inherit this proposal.

The fifth attempt produced a structurally valid original proposal, but its native attempt failed with runtime_protocol_error despite time remaining; its precise live diagnostic branch was not retained. Independent execution of the exact original adapter demonstrates a separate defect: after root process exit, the 200 ms empty-queue check may run before a reader delivers an already-read final agent_end event. Repair this proven defect by waiting for reader EOF and draining the queue, with a finite post-exit idle grace for inherited pipes. Queued output continues to drain under the original deadline and byte limits; a slow durable sink must not spend the idle grace. Completion must still require real assistant identity and agent_end events; timeout, cancellation, output bounds and descendant cleanup remain enforced. A reproduced defect is not asserted to be the fifth failure's proven cause. The same defective code exists in the formal module-author image, so separately admit both the changed compiler-v4 and module-author-v2 bindings using new real candidate outputs. Preserve the renderer, workbench, all other live profile/image bindings and every prior failed attempt.

The first real user-film module failed with model_error and a positive stop, without producing a module version. Its eight upstream responses all completed; the eighth proposed a full write, after which the SDK still needs an assistant turn. The live eight-call module cap therefore cannot finish that sequence. The original denial response was not retained, so it is not reported as an observed HTTP receipt. Increase only the authenticated film-module profile cap to 16, honoring a stricter operator cap and preserving all other profile budgets, input histories, deadlines and terminal outcomes. This belongs to the central model proxy; the admitted native worker and renderer remain pinned.

Independent review of the untouched proposal also found nonempty-group and renderCanvas transform rules it violated, plus a 20,150-character next-scene instruction against the existing 16,000 limit. Supply accurate fixed-library guidance and compact only autogenerated duplicated guidance when complete appearance-reference data would exceed the limit. Keep original predecessor source, exit state, identifiers and explicit user instructions intact; use pointers to scene/film data already present in the task rather than adding a worker contract field. Oversized references that still cannot fit fail explicitly. Renderer asset paths are not falsely advertised as readable native task files. A fresh standard production-run request may follow the repair under a new idempotency key, retaining the original failed run and the same adopted plan, project and knowledge release. No new retry API or historical result rewriting is needed.

That second actual production run completed five authentic, stopped module versions. The fifth module's complete appearance reference is 16,049 characters before any guidance, so even a 17,341-character compact instruction cannot fit. The original bound correctly stopped before a sixth operation or paid job; prose compaction alone cannot handle this case. Add a separately versioned author context with typed predecessor appearance data instead of embedding creative source inside instructions. Preserve the exact legacy v1/v2 fields and 16,000-character instruction ceiling. The new context retains that instruction ceiling, bounds the canonical complete reference to 512 KiB, and limits the actual input including the Skill catalog to the existing native reader's effective 2 MiB. It validates original source hashes, metadata, exit state, assets and reference identity, and fails oversized inputs before paid admission. Publish a new neutral module-author bundle while retaining historical bundle pins, then separately admit its changed native author; no knowledge publication, compiler admission, renderer or output-module change follows merely from this author-input change. Confirm those dependency boundaries against actual source and receipts. Preserve all five originals and both failed runs. At that stage a fresh standard attempt regenerated the twelve modules because the existing APIs did not support prefix reuse. Its immutable failure provides the trigger for the explicit continuation below.

The third run proves the typed handoff works beyond the former prose ceiling, but its fifth native module expires at its original 600-second author deadline. Its actual ledger records nine model requests: eight complete HTTP 200 responses and a ninth admitted request with no response at capture. This does not identify a provider failure or prove that source growth caused the timeout. The run failed after four real stopped module versions and before any whole-film snapshot or render. Retain that outcome and all original deadlines; simply restarting every module would discard completed work each time a later author times out.

Add an explicit optional `reuse_completed_prefix_from_run_id` to the standard production-run request. Initially admit only modern silent HyperFrames films, a failed source run with no render, a nonempty incomplete contiguous completed prefix, and identical owner, project, adopted plan, frozen content, film, knowledge release and creation configuration. Every started source child must be terminal with positive stop proof, and the source must have no blocked or draining state or resources. Validate the original completed operation, intent, package, input, module, source and predecessor bindings before accepting reuse. The new run retains the source run's complete frozen target list and the authentic prefix references and original completed intents, records explicit reuse provenance and a bounded acyclic lineage, and creates new suffix intents under its own run identity. Sources and packages are neither remapped nor relabeled as new native work. Preserve the complete old run, old operations, versions, inputs and deadlines byte for byte.

Revalidate the reuse receipt and original source chain before subsequent author admissions and final assembly. Missing, changed, noncontiguous, still active, wrong-owner or stale material must fail closed. Bound lineage and storage, keep idempotent replay behavior, expose reuse separately in public run metadata and record the remaining author and single-render budget. GET/list must not create continuation work. Existing native author, module package, namespace/import, source, clock, assembler, renderer and admission contracts remain unchanged. This is a new explicit production attempt, not revival of the expired native job. Validate the repair and retained actual prefix before deploying the workbench-only change and starting the unfinished suffix through the normal API.

The generated typed-context guide also clarifies that new author output may omit inherited layers only when they are proven permanently outside current and future planned views with no remaining dependency. Entry appearance, shared state and the absolute clock must remain equivalent, and the complete authenticated predecessor source, recipes, hashes and exit states remain unchanged. This addresses a possible cumulative-source growth risk; it is not asserted as the proven cause of the observed timeout. Historical v1/v2 guidance and contracts remain unchanged.

The first actual continuation submission exposed a facade boundary omitted by the initial tests and store-only dryrun: the production workflow deliberately refuses private Store methods, so `_version` dispatch raised before the new production journal was inserted. The server's HTTP 500 and the absence of the request key, new operations and renders are retained; its original submission intent is not replayed or rewritten. Resolve this with an explicit public read-only material method on the real workflow/store facade. It must validate version, package and corresponding assets on the admission caller's existing database connection, without opening a nested transaction. Test the actual workflow instance through HTTP admission, suffix revalidation and whole-film snapshot creation, and make the actual original-prefix dryrun use the same facade. Preserve the earlier store-only evidence with its demonstrated limit and use a distinct submission key after the reviewed workbench-only repair.

The sixth actual attempt completed all twelve authentic modules and their native stop receipts, then failed during its sole whole-film export. The original child reports `hyperframes_film_execution_failed` with positive stop proof after about 558 seconds, before its 3600-second deadline. A separate exact-snapshot sparse capture also failed at the first screenshot of frame 600 after frames 0, 299 and 599; this is relevant diagnostic evidence, not proof of the original export's underlying cause. Preserve both failures and original bytes, obtain surviving diagnostics, and use bounded isolated reproduction before selecting a renderer repair.

Extend the explicit reuse request narrowly for a full completed prefix when the source's sole draft render is failed, positively stopped and not cancelled. Preserve the existing incomplete-prefix/no-render branch. Validate all original module custody and the exact failed render intent, owner, project, request key/hash, configuration, film, ordered versions, targets, original snapshot and its complete module/asset inventory. Reject missing, extra, ambiguous, active or changed renders. Include the original stopped render document digest in the existing stopped-child receipt map. The new run copies only the original module items and module intents, retains its own empty draft/render fields and enters the normal single-render step with zero new author or audio admissions. Keep exact renderer/configuration/runtime identity matching and all original deadlines. Revalidate the source run, failed render and original snapshot before final assembly, and test the real HTTP/workflow path rather than an internal Store-only shortcut.

A fresh-browser frame-600 reproduction against the unchanged original image and snapshot fails at the first screenshot after seek/fonts completion, without a preceding scene or concurrent task render. An external diagnostic launcher appending only `--disable-accelerated-2d-canvas` passes that same frame, and all 36 original sparse checkpoints subsequently pass with idle pixel equality and no native errors. This supports the bounded Canvas2D launch repair; the original formal Job's lost process stderr still prevents asserting its exact lower-level cause. External launcher overrides are diagnostic evidence and do not become formal runtime admission.

The launch repair changes a trusted browser host and therefore requires a new immutable renderer image, host identity and technical admission. Existing modules retain the original four-field author runtime identity A, while every new execution must truthfully bind the admitted target B. Add a default-deny, operator-owned source-runtime policy P with complete A/B identities, source configuration SHA, independently admitted B evidence, before/after host maps and runtime fingerprints, identical engine/capability/assets/license/library supply, and the exact owner/project/source-run/film/original-snapshot/ordered complete package scope. Only the reviewed browser launch host delta is eligible; P cannot authorize changed module profiles or arbitrary runtime substitution. Requests and Agent output cannot supply or authorize P.

Avoid hash cycles by first admitting B independently, then hashing P without a target creation-configuration SHA, and finally including P in the new current creation configuration C. A server-derived receipt binds the original stopped source A, the new run, C, P and the complete original package inventory. Existing current-configuration checks remain exact C-to-current; copied module operations retain their authenticated A configuration, while the new draft operation uses C. Only full-prefix reuse with zero new author/audio work may cross this exact policy. Revalidate P and the source receipt before assembly. Assembly accepts the authenticated author A separately from execution B, records both and P provenance, and preserves all old packages, inputs, native evidence and the old snapshot byte for byte. New project/snapshot/renderer/Kubernetes/output verification continues to require the real B image, runtime, hosts and admission. Without an exact policy match, historical strict identity checks remain in force.

The source configuration has a nonempty Manim consumer context even though this film has no resource work. Its target formal-release identity and consumer admission must therefore be independently replayed for B. Permit only the exact A-to-B formal-release and consumer-admission binding change; keep the producer, resource image, helper bytes and all other consumer fields identical, and pin both admission proofs in P. This metadata rebinding does not authorize a resource task or a new module author.

New long-film exports use an operator-owned wall-clock ceiling of 10800 seconds. This changes execution time rather than film time: the maximum film remains 300 seconds/7200 frames at 24 fps, the short-film default remains 600 seconds and its existing 1200-second validation ceiling remains unchanged. All previously frozen timeout values, snapshot hashes, operation deadlines and terminal outcomes stay intact. Existing active snapshots have no supported live extension; a longer budget is frozen only in a separately admitted new snapshot and ordinary fresh recovery request.

The shared trusted limit must agree in Workbench and the immutable renderer. Snapshot validation, exporter execution, Workbench deadline, Kubernetes Job lifetime and client waits continue to derive from that snapshot's explicit budget; cleanup allowances do not substitute for a longer export budget. Measure the actual new images' Python limit and boundary behavior in addition to runtime/host fingerprints, then independently admit the new target and its unchanged Manim consumer before installing its exact P/C. The only additional permitted runtime behavior change is the reviewed wall-clock ceiling; original engine, pixel-producing hosts, profiles, capabilities, assets, licenses, producer and package bytes remain exact. A fresh complete-film request still reuses original A's twelve authenticated modules, performs no author/audio/resource work, and admits one new whole-film export.
